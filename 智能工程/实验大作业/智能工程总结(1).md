# 智能工程课程设计：基于ROS2的移动机器人自主建图与多点导航系统实现

## 1. 项目概述

本项目基于 ROS2 (Jazzy) 和 Gazebo 仿真环境，以 TurtleBot3 机器人为平台，实现了未知环境下的自主探索建图与已知环境下的多点自主导航功能。系统集成了 `slam_toolbox`、`nav2_bringup` 以及基于前沿探索的 `explore_lite` 算法，并通过自定义 ROS2 节点 (`auto_navigator`) 实现了定点巡航逻辑。项目的启动流程与参数配置通过 Shell 脚本进行了封装，实现了系统各模块的自动化调用。

## 2. 系统框架与文件结构

项目主要包含于 `ros2_project_ws` 工作空间，其核心功能模块分布如下：

### 2.1 脚本控制模块 (scripts)
该目录包含用于流程控制的 4 个 Shell 脚本，用于依次启动各项功能：
- **1_mapping.sh**：配置环境变量并启动 Gazebo 仿真、2D SLAM 节点以及 `explore_lite` 自主探索节点。
- **2_save_map.sh**：调用 `nav2_map_server` 的 `map_saver_cli` 工具，将 SLAM 生成的栅格地图保存至本地。
- **3_navigation.sh**：加载静态地图文件，启动 Nav2 导航栈，并运行自定义的多点导航控制节点。
- **4_auto_explore.sh**：用于独立启动探索算法节点的辅助脚本。

### 2.2 核心功能包 (src)
- **course_demo**：自定义的 ROS2 功能包，包含系统集成与逻辑控制代码：
  - `launch`：包含 `slam_demo.launch.py` 和 `nav_demo.launch.py`。前者负责组合启动 Gazebo、SLAM Toolbox、Nav2 (不含 AMCL) 及 Explore Lite 节点；后者负责组合启动 Gazebo、Nav2 (含 AMCL) 及 RViz2。
  - `course_demo`：包含 Python 编写的节点，其中 `auto_navigator.py` 实现了多目标点序列导航的控制逻辑。
  - `param` 与 `rviz`：分别存储 Nav2/Explore Lite 的配置文件及 RViz2 界面显示配置。
- **m-explore-ros2**：引入的开源探索功能包，其 `explore_lite` 节点用于根据地图边界 (Frontier) 生成导航目标点，驱动机器人完成未知区域的探索。

### 2.3 地图存储 (maps)
存放保存的二维栅格地图数据 (`my_map.pgm`) 与元数据配置文件 (`my_map.yaml`)。

## 3. 核心算法与功能实现

### 3.1 仿真地图与环境配置
项目采用 Gazebo 作为三维物理仿真引擎。系统配置调用了 `turtlebot3_gazebo` 官方标准的 **TurtleBot3 World** 三维地图环境。该环境在物理仿真层具备以下特征：
- **空间结构布局**：仿真场景为一个封闭式矩形平面区域（约 5m × 5m），外围由实体墙壁界定。区域内部非均匀散布着由六棱柱、圆柱和立方体等几何体构成的静态障碍物。
- **建图与导航验证特性**：障碍物的排列形成了一系列回环通道、不规则转角及开阔区域。这种结构提供了丰富的几何特征（如棱角和直线边缘），有助于验证 2D 激光雷达的空间扫描性能以及 SLAM 算法的局部特征匹配与回环检测精度。
- **机器人实体模型**：仿真采用 TurtleBot3 Burger 构型，其物理模型搭载了 360 度 2D 激光雷达传感器与双轮差速驱动组件，能够在环境中模拟产生符合运动学约束的里程计数据。

### 3.2 基于前沿探索的自主建图
在未知环境中，系统采用 `slam_toolbox` 的在线异步建图 (Online Async SLAM) 模式，利用激光雷达和里程计数据实时更新二维栅格地图。在此过程中，`explore_lite` 节点通过分析当前占用栅格地图，提取已探索区域与未探索区域的交界线（即前沿），并计算目标点发送至 Nav2 导航栈。机器人自主移动至各前沿点，直至环境中不再存在可达的未知区域，完成全图构建。

### 3.3 基于 Nav2 的多点自动巡航
在已构建地图的环境下，系统通过 Nav2 导航栈完成定位与路径规划。Nav2 采用 AMCL 算法进行全局定位，并利用代价地图 (Costmap) 进行全局路径规划与局部避障。
自定义控制节点 `auto_navigator.py` 实现了业务层的控制逻辑：
1. **位姿初始化**：启动后，节点通过 API 发送初始位姿坐标 `(0.0, 0.0, 0.0)`，完成定位系统的初始化。
2. **序列目标导航**：程序预设了四个目标点坐标 `(1.5, 1.5)`、`(2.0, -1.5)`、`(4.0, 1.0)` 和 `(0.0, 0.0)`。节点调用 `nav2_simple_commander` API 的 `goToPose` 方法，以阻塞等待的方式依次向各目标点发送导航请求。
3. **可视化标记反馈**：在导航过程中，节点实例化 `MarkerArray`，向 `/waypoints` 话题发布包含球体几何模型和序号文本的可视化标记，用于在 RViz2 中显示各个目标点的位置。

## 4. 总结

本项目构建了一个完整的 ROS2 移动机器人仿真系统，涵盖了传感器数据处理、SLAM 建图、自主探索以及路径规划导航等核心环节。在实现过程中，系统有效地整合了现有开源算法栈，并通过自定义节点与状态管理脚本实现了模块间的时序控制与流程自动化，达到了自主建图与多点导航的设计要求。
